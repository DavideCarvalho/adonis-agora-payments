An app can run payments **standalone** (its own gateways and credentials, its own webhooks, its
own billing tables) and still appear in another app's [console](/docs/payments/dashboard), next to
that console's own data. Typically the Hub's console shows the Hub's payments and, in the same
**App** picker, each app that charges on its own.

Two sides take part:

- **the console app** (the Hub) lists the other apps under `apps` in `config/payments_dashboard.ts`;
- **each owning app** answers that console with `consoleCommands` in its `config/payments.ts`.

The console reads the owning app's billing tables itself, and asks the owning app to run every
action. The owning app's gateways are only ever called by the owning app.

## The console app

```ts title="config/payments_dashboard.ts"
import env from '#start/env'
import { defineConfig } from '@adonis-agora/payments/dashboard'

export default defineConfig({
  appLabel: 'Hub',
  authorize: async (ctx) => {
    const user = await ctx.auth.authenticate()
    if (user.role === 'finance') {
      return {
        allowed: true,
        apps: '*',
        capabilities: ['payments:console:read', 'payments:console:refund', 'payments:console:subscriptions:*'],
      }
    }
    if (user.role === 'support') {
      return { allowed: true, apps: ['entre-textos'], capabilities: ['payments:console:read'] }
    }
    return { allowed: false }
  },
  apps: {
    'entre-textos': {
      label: 'Entre Textos',
      // A connection in THIS app's config/database.ts that reaches the app's billing tables,
      // and the app's `billing.schema`.
      store: { connection: 'entretextos', schema: 'entretextos' },
      // A connection in THIS app's config/redis.ts and the app's `consoleCommands.prefix`. With
      // @adonis-agora/crypto in both apps, that is all (see "Authenticating the console").
      controlPlane: { connection: 'main', prefix: 'entretextos' },
    },
    eduliberta: {
      label: 'EduLiberta',
      store: { connection: 'eduliberta', schema: 'eduliberta' },
      controlPlane: {
        connection: 'main',
        prefix: 'eduliberta',
        // Without @adonis-agora/crypto or authkit: the same secret as the app's.
        secret: env.get('EDULIBERTA_CONSOLE_SECRET'),
      },
      // Browse only from here.
      actions: false,
    },
  },
})
```

| Option | Description |
| --- | --- |
| `apps` | The other apps, by a key of 1–64 characters (`A-Z a-z 0-9 _ . -`). The key is what the URL carries: `?app=entre-textos`. |
| `apps.<key>.label` | The name in the App picker. Defaults to the key. |
| `apps.<key>.store.connection` | A Lucid connection of this app that reaches the other app's billing tables. Default: the default connection. |
| `apps.<key>.store.schema` | The other app's `billing.schema`. Omit it when that app has none. |
| `apps.<key>.controlPlane.connection` | The `@adonisjs/redis` connection to publish on. Both apps must use the same Redis server. Default: the default connection. |
| `apps.<key>.controlPlane.prefix` | The other app's `consoleCommands.prefix`. |
| `apps.<key>.partition` | That app's crypto partition and authkit app name. Default: the key. |
| `apps.<key>.controlPlane.crypto` | Explicit crypto: `{ cipher, key?, owns? }`. Automatic with `@adonis-agora/crypto` in this app; `false` turns that off. |
| `apps.<key>.controlPlane.token` | Token mode: this console's token for that app (`authkitTenantToken`, or your function). Automatic with authkit's calls between apps; `false` turns that off. |
| `apps.<key>.controlPlane.publicKey` | Token mode without `crypto`: the app's console-command key, as `node ace payments:console-key` prints it there. |
| `apps.<key>.controlPlane.secret` | Shared-secret mode: the same secret as the app's `consoleCommands.secret`. |
| `apps.<key>.actions` | `false` to only browse that app here. Default `true`. |
| `apps.<key>.timeoutMs` | How long an action waits for the app to answer. Default `15000`. |
| `appLabel` | The name of this console's own app in the picker. Default `This app`. |

The console app needs `@adonisjs/lucid` and `@adonisjs/redis`. A malformed entry fails the boot.

### Who sees and does what

`authorize` decides it, with two fields:

- `apps`: the other apps this person may pick (`'*'` or a list). An app outside it is not offered,
  and `?app=` naming it answers `403`. Omitted, every app is offered, except with
  [organizations](/docs/payments/organizations) on and a person confined to some of them: another
  app is then offered only when `apps` names it.
- `capabilities`: what this person may do on another app. Omitted, the person gets the whole
  console set (`payments:console:read`, `payments:console:write`) and the owning app's `actions`
  allow-list decides; a list narrows it (a malformed value grants nothing).
  `payments:console:*` (or `payments:*`) grants everything.
- `access: 'read'`: this person may only read other apps, whatever `capabilities` says.

| Action | Capability |
| --- | --- |
| Refund a payment | `payments:console:refund` (or `payments:refund`) |
| Cancel a subscription | `payments:console:subscriptions:cancel` (or `payments:subscriptions:cancel`) |
| Resume a subscription | `payments:console:subscriptions:resume` (or `payments:subscriptions:resume`) |
| Re-price a subscription | `payments:console:subscriptions:reprice` (or `payments:subscriptions:reprice`) |
| Retry a failed webhook event | `payments:console:webhooks:retry` (or `payments:webhooks:retry`) |
| Record how a dispute ended | `payments:console:disputes:resolve` (or `payments:disputes:resolve`) |

`payments:console:write` grants every action.

The owning app must allow the same action too (below): both sides have to say yes.

The subscription actions are the console's `POST <path>/api/subscriptions/:id/cancel`, `/resume`
and `/reprice` routes (`{ atPeriodEnd }`, nothing, `{ amount, cycle? }`), which the console also
answers for its own subscriptions.

### Organizations

A federated app is shown **whole**: when the owning app has
[organizations](/docs/payments/organizations) on, the console sees every one of its organizations'
rows, and its actions run over the app's whole store, like an operator with `tenants: '*'` in the
app's own console. The boundary is the console's `apps` grant: give an app only to the people who
may see all of its billing. The console's own Organization picker does not apply to another app,
and is hidden while one is picked.

## Each owning app

```ts title="config/payments.ts (the owning app)"
import { defineConfig, payments } from '@adonis-agora/payments'
import env from '#start/env'

export default defineConfig({
  default: 'stripe',
  providers: {
    stripe: payments.stripe({
      apiKey: env.get('PAYMENTS_STRIPE_KEY'),
      webhookSecret: env.get('PAYMENTS_STRIPE_WEBHOOK_SECRET'),
      currency: 'brl',
    }),
  },
  billing: { schema: 'entretextos' },
  consoleCommands: {
    prefix: 'entretextos',
    connection: 'main',
    actions: ['refund', 'cancelSubscription', 'resolveDispute'],
    // With @adonis-agora/crypto in this app, nothing else (see "Authenticating the console").
    // Without it: secret: env.get('ENTRETEXTOS_CONSOLE_SECRET'),
  },
})
```

| Option | Description |
| --- | --- |
| `consoleCommands: true` | Answer the console on the default Redis connection, with the app's package name as the prefix, and run no action. The console still reads the tables. |
| `consoleCommands.prefix` | The prefix the console app names in `controlPlane.prefix`. |
| `consoleCommands.connection` | The `@adonisjs/redis` connection to listen on. |
| `consoleCommands.actions` | The actions another console may ask for: `refund`, `cancelSubscription`, `resumeSubscription`, `repriceSubscription`, `retryWebhook`, `resolveDispute`. Every one not listed is refused with `403`. Default: none. |
| `consoleCommands.verifyTenant` | Token mode: checks the console's token (`authkitTenantVerifier`, or your function). Automatic with authkit's calls between apps, and on a control plane; `false` turns that off. |
| `consoleCommands.partition` | Token mode: the partition the console's token must be for. Default: the `prefix`. |
| `consoleCommands.crypto` | Explicit crypto: `{ cipher, key?, owns? }`. Automatic with `@adonis-agora/crypto` in this app; `false` turns that off. |
| `consoleCommands.secret` | Shared-secret mode: the same secret as the console's `controlPlane.secret` (16+ characters). |
| `consoleCommands.idempotency` | Where the app keeps what it already ran. Default: its Redis, for 24 hours. `memoryIdempotencyStore()` keeps it in the process (one instance only). |

Every web instance of the app listens, and exactly one of them runs each action, through the same
code as the app's own console: its gateway driver, its validation, its webhook handlers and its
audit trail. The audit row names the console's person and the console:

```
ops@example.com (via Hub)
```

The app logs one line per action:

```
[payments] federated console: refund pay_3Nq… by ops@example.com (via Hub)
```

`consoleCommands` does not apply to a [tenant](/docs/payments/control-plane): a tenant's payments
are operated on its control plane.

The app keeps charging as before, from its own code:

```ts title="app/controllers/enrollments_controller.ts"
import type { HttpContext } from '@adonisjs/core/http'
import { getPayments } from '@adonis-agora/payments/services/main'
import Enrollment from '#models/enrollment'

export default class EnrollmentsController {
  async pay({ params, response }: HttpContext) {
    const enrollment = await Enrollment.findOrFail(params.id)
    const payment = await getPayments().driver('pix').charge({
      customerId: enrollment.customerId,
      amount: enrollment.price, // integer cents
      externalReference: enrollment.id,
    })
    return response.json({ pixCode: payment.pixCode })
  }
}
```

A refund made from the Hub lands in the same tables and the same webhook flow as one made in the
app's own console:

```ts title="app/services/refund_report.ts"
import { getBillingStore } from '@adonis-agora/payments/services/main'

export async function refundsMadeFromTheHub() {
  const rows = await getBillingStore().listAuditEvents({ action: 'payment.refunded' })
  return rows.filter((row) => row.actor?.endsWith('(via Hub)'))
}
```

## Idempotency

Every action sent to another app carries an `Idempotency-Key` header. The console's page sends a
new one with each action; an API client must send its own (8–200 characters of
`A-Z a-z 0-9 _ . : -`), or the action answers `400`. A `dryRun` needs none.

The owning app runs a key once:

- the same key again (a retry after a timeout, a second click that reached the server) answers the
  first run's answer, and nothing runs twice;
- the same key with other arguments answers `422`;
- a key whose run has not answered yet, or was interrupted, answers `409` until it expires
  (24 hours): check the payment before sending the action again with a new key.

On Stripe, the key also reaches the gateway, which deduplicates the refund itself.

## What the console reads, and what it never sees

The console reads the other app's `billing_*` tables with its own connection and never writes
there. On Postgres, give that connection's role read access to them, and nothing else:

```sql
GRANT USAGE ON SCHEMA entretextos TO hub_role;
GRANT SELECT ON
  entretextos.billing_customers,
  entretextos.billing_subscriptions,
  entretextos.billing_payments,
  entretextos.billing_webhook_events,
  entretextos.billing_disputes,
  entretextos.billing_usage_events,
  entretextos.billing_audit_events
TO hub_role;
```

If the apps live in different databases, declare a Lucid connection to the other database in the
console app's `config/database.ts` and name it in `store.connection`.

For a picked app, the console shows its overview and health, payments and their detail,
subscriptions and their detail, customers, disputes, the webhook ledger and the audit trail. Before
anything is shown:

- a customer's document number is partially masked (`***.456.789-**`, `12.345.678/****-**`);
- a payment method is reduced to its brand and last 4 digits, and a card number in a message to its
  last 4;
- raw gateway payloads, headers, signatures, PIX codes and anything named like a key, secret or
  token are dropped.

The gateways' credentials and webhook secrets stay in the owning app: the console never has them,
and no command or answer carries them. What a gateway can do (refunds, disputes, subscription
changes) comes from the app as yes/no answers.

## Authenticating the console

Commands travel over Redis, and Redis is not a trust boundary: whoever can publish on it (another
app on a shared instance, a leaked password, an SSRF) must not be able to send a refund, claim to
be any viewer, or forge an answer. So every command is authenticated, and a setup that cannot
authenticate **does not boot** (below). None of authkit, authz or crypto is required: each mode
works on its own, and every automatic piece can be replaced by your own function.

| Setup | Lines in `consoleCommands` / `controlPlane` | Grants |
| --- | --- | --- |
| Together: the Hub with crypto embedded, apps its crypto tenants | none | none |
| Crypto as a separate app | none | the console's crypto client: `crypto:seal:console-*` |
| Authkit without crypto | none (app-call token + key directory) | console app: `payments:console:*` (or narrower) on the owning app, in authkit, once: without crypto the token is mandatory and caps every command |
| Neither | the same `secret` on both sides | none |

**Mixed Hubs.** A Hub with crypto and authkit can federate crypto apps and authkit-only apps with
no lines either. It picks the way per app at the first command, and keeps the choice for five
minutes: an app that published its key in authkit's key directory (an app does so only when no
crypto reaches it) gets an authkit app-call token sealed to that key; any other app gets crypto.
The boot log says `auto (authkit key directory if the app publishes one, else crypto (…))`. In crypto
mode the token is optional: if authkit cannot mint it (no grant, `invalid_target`), the command is
sent crypto-only and the console warns once, naming the grant to add. An app that does not answer
makes the console decide again on the next command.

Token mode needs the app's `APP_KEY`: it is read from `config/app.ts` (`appKey`), else from the
default entry of `config/encryption.ts`, else from the `APP_KEY` environment variable.

### Together with `@adonis-agora/crypto`: nothing to configure

When `@adonis-agora/crypto` is booted in the console app and in the owning app (the usual Agora
setup: crypto embedded in the Hub, each app a crypto tenant of the Hub), the two find each other.
Neither `consoleCommands` nor `controlPlane` needs an authentication line:

```ts title="config/payments.ts (the owning app)"
consoleCommands: {
  prefix: 'entretextos',
  actions: ['refund', 'cancelSubscription', 'resolveDispute'],
},
```

```ts title="config/payments_dashboard.ts (the Hub)"
apps: {
  'entre-textos': {
    store: { connection: 'entretextos', schema: 'entretextos' },
    controlPlane: { prefix: 'entretextos' },
  },
},
```

- Commands are sealed with the **`console-payments`** key (`aes256-gcm`) of the owning app's
  crypto partition. Nothing in them (action, payment, amount, viewer) is readable on Redis; each
  command is one `encrypt` row and one `decrypt` row in crypto's audit trail.
- **The partition rule:** the console seals for `apps.<key>.partition`, which defaults to the key.
  It must be the owning app's crypto partition: set `partition: 'entre-textos'` on the entry when
  the key differs.
- **The key is created for you**: by the Hub at boot when crypto is embedded there, by the owning
  app when its crypto runs in-process, or by the crypto server on the console's first seal. A
  tenant app that finds no key at boot logs one info line saying so (and, for a crypto server with
  `sealProvisioning` off, the command to run:
  `node ace crypto:keys:create console-payments --type aes256-gcm --application entre-textos`).
- **No grant on the owning app:** a crypto server lets an app decrypt its own `console-*` keys
  without one (an existing `crypto:decrypt:console-*` grant is harmless).
- When crypto is a **separate app** (the console is a crypto tenant too), the console seals through
  the channel its `config/crypto.ts` already has, asking the crypto server to encrypt with the
  owning app's key. Its crypto client needs the seal-only grant `crypto:seal:console-*` (encrypt
  for another app, never decrypt). A crypto server too old for it answers an error that says to
  upgrade `@adonis-agora/crypto` there, or to configure `crypto` explicitly.

Each side logs what it resolved, once at boot:

```
[@adonis-agora/payments] console commands: crypto (auto, key console-payments); actions on
[@adonis-agora/payments] console commands to "entre-textos": crypto (auto, key console-payments, partition entre-textos)
```

`crypto: false` on `consoleCommands` or on `controlPlane` turns the automatic mode off. Any
explicit `crypto`, `secret`, `token` or `verifyTenant` is used as given, and automatic crypto is
not added on top.

#### With authkit too: a token from its calls between apps

When `@adonis-agora/authkit-client` is configured for
[calls between apps](/docs/authkit/calls-between-apps) (`service` + `apps`), the console also asks
it for a token for the owning app, and the owning app verifies it with authkit, again with no lib
configuration. With crypto, the command is sealed **and** carries the token: the strongest setup.

- The token's audience is the owning app, so it answers for this app whatever its partition says;
  the audit row names the calling app: `ops@example.com (via Hub, app hub, client hub-client)`.
- Its capabilities cap the command, narrowed by the viewer's. Grant the console app, in authkit,
  `payments:console:*` (or narrower, below) on each app it manages.
- A command without a token is still accepted when crypto sealed it (the key authenticates it), so
  apps move over one at a time.
- Without crypto, the token is sealed to the app's `APP_KEY`-derived key. The app publishes its
  public half in authkit's **key directory** at boot (purpose `console:payments`), and the console
  reads it there, over authkit's authenticated API, never from Redis: nothing to copy. An explicit
  `controlPlane.publicKey` still wins; with neither, the console fails the boot saying so.
- `token: false` on `controlPlane` and `verifyTenant: false` on `consoleCommands` turn it off.

On a payments [control plane](/docs/payments/control-plane), the owning app also accepts tokens its
own `controlPlane.verifyTenant` accepts. That is safe: every command needs a
`payments:console:*` capability, which a tenant's token (`payments:charge`, `payments:refund`, …)
does not carry.

### The capabilities a command needs

The console always sends the viewer's capabilities: those its `authorize` returned that reach the
payments console (another lib's, like `flags:console:*`, are dropped), or the whole console set
(`payments:console:read`, `payments:console:write`) when `authorize` returns none; the owning
app's `actions` allow-list still decides. `access: 'read'` in the `authorize` answer keeps reads
only, and a malformed `capabilities` value grants nothing. The owning app refuses a command that
carries no capabilities (`403`, code `capabilities-required`): missing never means everything. A
refusal says who lacks the capability: "the console's token lacks …" or "the viewer lacks …".

| Command | Console capability | Also accepted from a viewer |
| --- | --- | --- |
| Read the app's profile (what its gateways can do) | `payments:console:read` | `payments:read` |
| Refund a payment | `payments:console:refund` | `payments:refund` |
| Cancel a subscription | `payments:console:subscriptions:cancel` | `payments:subscriptions:cancel` |
| Resume a subscription | `payments:console:subscriptions:resume` | `payments:subscriptions:resume` |
| Re-price a subscription | `payments:console:subscriptions:reprice` | `payments:subscriptions:reprice` |
| Retry a failed webhook event | `payments:console:webhooks:retry` | `payments:webhooks:retry` |
| Record how a dispute ended | `payments:console:disputes:resolve` | `payments:disputes:resolve` |

`payments:console:write` grants every action, and `payments:console:*`, `payments:*` and `*` grant
everything. A **token** (token mode) must carry the console capability; the right-hand column
applies only to the viewer capabilities the console's `authorize` returns.

### Misconfiguration fails at boot

Both errors are a `ConsoleAuthConfigError` (exported) and end with "Run `node ace agora:doctor` to
see every Agora lib's console auth at once." In token mode the boot log names the app's public key
by a short id only; `node ace payments:console-key` prints the key itself. A console whose command
gets no answer says `no instance of "<app>" answered within <n>s — the app may have refused the
command (check its logs, or run \`node ace agora:doctor\` there)`. A garbage or refused message on
the command channel is dropped and logged once per reason; it never stops the app.

- **Owning app:** `consoleCommands` set, and no mode resolves (no crypto booted, no `secret`, no
  usable `verifyTenant` + `APP_KEY`): the web process does not start, and the error names the three
  ways to fix it.
- **Console:** an entry of `apps` that may send actions (`actions` is not `false`) and has no mode:
  the console does not start, and the error suggests `actions: false` to browse it only.
- `ace` commands never fail for this (they do not start the channel).

`node ace agora:doctor` shows the mode each side resolved (`payments.console-commands`), and with
`--deep` checks that this process can use the crypto key (`payments.console-commands-key`: the app
encrypts and decrypts a probe, or finds the key when its grant is decrypt only; the console seals
one for each app).

### Explicit crypto

Set `crypto` yourself to use another key name, a crypto client other than the app's own, or
another cipher altogether:

```ts title="config/payments.ts (the owning app)"
import crypto from '@adonis-agora/crypto/services/main'

consoleCommands: {
  prefix: 'entretextos',
  crypto: { cipher: () => crypto.client!, key: 'console-payments' },
  actions: ['refund'],
},
```

```ts title="config/payments_dashboard.ts (the console)"
import crypto from '@adonis-agora/crypto/services/main'
import { serviceCipher } from '@adonis-agora/crypto'

controlPlane: {
  prefix: 'entretextos',
  crypto: { cipher: () => serviceCipher(crypto.service, 'entre-textos') },
},
```

`crypto.cipher` is anything with `encrypt({ key, plaintext, aad, context })` and
`decrypt({ key, ciphertext, aad, context })`; pass a function, since config files are read before
crypto is ready. The answer carries a MAC under a one-off secret that travelled inside the
encrypted command, so a forged answer is ignored.

### With authkit (token mode)

1. In authkit, create a **service-tenant client** for the console, for the resource
   `urn:agora:payments`, with `partition` set to the owning app (`entretextos`, or whatever you set
   as `consoleCommands.partition`) and the console capabilities it may use there
   (`payments:console:read`, `payments:console:refund`, … or `payments:console:*`). One client per
   app the console manages.
2. In the owning app, set `consoleCommands.verifyTenant` to `authkitTenantVerifier({ issuer,
   resource: 'urn:agora:payments' })`. The app needs its `APP_KEY`.
3. In the owning app, run `node ace payments:console-key`. It prints the public half of a key
   derived from `APP_KEY` and the `prefix` (the app also logs it at boot). It is public: put it
   in the console app's environment as is.
4. On the console, set `controlPlane.token` to `authkitTenantToken({ issuer, clientId,
   clientSecret, resource: 'urn:agora:payments' })` with that client, and `controlPlane.publicKey`
   to what step 3 printed.

What happens on each command:

- The console seals the whole command, its token included, to the app's key. It takes that key
  from its own configuration, never from Redis, so nobody on Redis can make it seal to their key.
- The app opens it, refuses it if it is over a minute old, and verifies the token. The token's
  `partition` must be this app's (`403` otherwise); its capabilities cap what the command may do,
  and the viewer capabilities the console sends narrow them.
- The audit row names the token's client too: `ops@example.com (via Hub, client hub-console)`.
- A refused token answers `401`; the console drops its cached token and fetches a new one.

A new `APP_KEY` (or `prefix`) makes a new key: run `payments:console-key` again and update the
console. With `crypto` too, no public key is needed, and each command must carry a valid token.

### Without authkit or crypto (shared secret)

Generate one random secret per pair of apps (16 characters at least; `openssl rand -base64 32`
prints a good one) and set the same value on both sides:

```ts title="config/payments_dashboard.ts (the console app)"
controlPlane: {
  connection: 'main',
  prefix: 'entretextos',
  secret: env.get('ENTRETEXTOS_CONSOLE_SECRET'),
},
```

```ts title="config/payments.ts (the owning app)"
consoleCommands: {
  connection: 'main',
  prefix: 'entretextos',
  secret: env.get('ENTRETEXTOS_CONSOLE_SECRET'),
  actions: ['refund', 'cancelSubscription', 'resolveDispute'],
},
```

Every command and every answer carries an HMAC under that secret, bound to the app's `prefix`.
The command is readable on Redis (not encrypted). In this mode the console is trusted to say who
the viewer is and what they may do (the app still applies its `actions` allow-list), so treat the
secret like an admin credential for the actions you allowed, and rotate it on both sides when
someone who had it leaves.

### Bring your own

Nothing above requires an Agora lib. Each piece is a plain function:

```ts title="Your own token and verifier (any IdP, a JWT library, API keys)"
// The console
controlPlane: {
  prefix: 'entretextos',
  token: async () => myIdp.clientCredentialsToken({ audience: 'entretextos-payments' }),
  publicKey: env.get('ENTRETEXTOS_CONSOLE_KEY'),
},

// The owning app
consoleCommands: {
  prefix: 'entretextos',
  verifyTenant: async ({ token }) => {
    const claims = await verifyJwt(token, { audience: 'entretextos-payments' })
    if (!claims) return null
    return { partition: 'entretextos', capabilities: claims.scope.split(' '), clientId: claims.sub }
  },
},
```

```ts title="Your own KMS, Vault transit or HSM"
const vault = {
  encrypt: async ({ key, plaintext, aad }) => ({
    ciphertext: await vaultTransit.encrypt(key, plaintext, aad),
  }),
  decrypt: async ({ key, ciphertext, aad }) => ({
    plaintext: await vaultTransit.decrypt(key, ciphertext, aad),
  }),
}

// Both sides. `owns` tells this cipher's ciphertext apart (default: `agora:ct1:<key>:`).
crypto: { cipher: vault, key: 'console-payments', owns: (c) => c.startsWith('vault:v1:') },
```

```ts title="Your own authorization (instead of authz)"
authorize: async (ctx) => {
  const user = await ctx.auth.authenticate()
  const capabilities = {
    admin: ['payments:console:*'],
    finance: ['payments:console:read', 'payments:console:refund'],
    support: ['payments:console:read'],
  }[user.role]
  return capabilities ? { allowed: true, apps: '*', capabilities } : { allowed: false }
},
```

### Moving from one to the other

An app accepts every mode it has configured at once (`crypto`, `verifyTenant`, `secret`), so it
can take both the old and the new while its consoles move over; remove the old one once every
console has switched. An explicit `verifyTenant` together with `crypto` makes the token required
for crypto commands too.

<Callout type="warn">
  Upgrading from an earlier release: an app with `consoleCommands` and no way to authenticate now
  fails its boot (install `@adonis-agora/crypto`, or set `secret` or `verifyTenant`), and so does a
  console with an app it may act on and no way to authenticate (or set `actions: false`). The
  default crypto key is now `console-payments` (it was `payments-console`). A console token needs
  the `payments:console:*` capabilities; `payments:read` / `payments:refund` on a token no longer
  make it a console.
</Callout>

## Using the console

With `apps` set, the topbar's **App** picker lists this app first, then the other apps, each tagged
**federated**. Picking one puts it in the URL (`?app=entre-textos`), so a link or a reload keeps
it; picking this app removes it. While another app is picked, a note at the top of every page says
its data comes from its own store and that actions are sent to it, or that it is read-only here,
and the Organization picker is hidden. The Refund, Retry and Record outcome buttons are disabled for
a read-only app.

When the app does not answer (it is down, `consoleCommands` is off, or the two sides share no
authentication), an action fails at once with `503` and a message naming the app. Its tables still
read.

## The API

Every console API route takes `?app=<key>`. `GET <path>/api/apps` lists what the picker offers:

```json
{
  "local": { "id": null, "label": "Hub" },
  "topology": "control-plane",
  "tenants": [{ "id": "agora-shop", "label": "agora-shop", "mode": "control-plane", "actions": "here" }],
  "apps": [
    { "id": "entre-textos", "label": "Entre Textos", "mode": "federated", "actions": "app" },
    { "id": "eduliberta", "label": "EduLiberta", "mode": "federated", "actions": "none" }
  ],
  "selected": null
}
```

`apps` are the federated apps this person may pick. `actions` says who runs actions on that app's
data: `app` (they are sent to the app) or `none` (browse only). `tenants` are the apps calling this
app as their [control plane](/docs/payments/control-plane): their payments are this app's own rows,
shown without `?app=`. `selected` echoes `?app=` when it names one of `apps`.

```sh
curl -X POST 'https://hub.example.com/payments/api/payments/pay_3Nq/refund?app=entre-textos' \
  -H 'Idempotency-Key: refund-pay_3Nq-2026-11-19' \
  -H 'Content-Type: application/json' \
  -d '{ "amount": 1000 }'
```

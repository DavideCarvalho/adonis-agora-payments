Each pattern below is complete enough to adapt. They all assume the same two habits: an
`externalReference` that points at your own row, and business logic that lives in a
[webhook handler](/docs/payments/webhooks) rather than next to the `charge()` call.

## One-off Pix, from checkout to grant

The most common Brazilian flow. Three pieces: create the local record, charge, grant on
confirmation.

```ts title="app/services/checkout_service.ts"
import { ensureCustomer, getPayments } from '@adonis-agora/payments'

export async function startCheckout(user: User, plan: Plan) {
  const payments = getPayments()
  const driver = payments.driver('pix')

  const customer = await ensureCustomer(driver, user.billingCustomerId, {
    name: user.fullName,
    email: user.email,
    taxId: user.cpfCnpj ?? undefined,
  })
  if (customer.id !== user.billingCustomerId) {
    user.billingCustomerId = customer.id
    await user.save()
  }

  const order = await Order.create({
    userId: user.id,
    planId: plan.id,
    total: plan.priceCents,
    status: 'awaiting_payment',
  })

  const payment = await driver.charge({
    customerId: customer.id,
    amount: order.total,
    description: plan.name,
    externalReference: order.id,
    idempotencyKey: `order:${order.id}`,
  })

  return { order, pix: { code: payment.pixCopiaECola, qr: payment.pixQrCode } }
}
```

```ts title="app/payment_handlers/payment_succeeded.ts"
import { inject } from '@adonisjs/core'
import type { WebhookEvent } from '@adonis-agora/payments'

@inject()
export default class PaymentSucceededHandler {
  static readonly eventType = 'payment.succeeded'

  constructor(private grants: GrantService) {}

  async handle(event: WebhookEvent): Promise<void> {
    const orderId = (event.data as { externalReference?: string }).externalReference
    if (!orderId) return

    // The inner idempotency guard: this transition is only possible once.
    const updated = await Order.query()
      .where('id', orderId)
      .andWhere('status', 'awaiting_payment')
      .update({ status: 'paid', paidAt: DateTime.now() })

    if (updated[0] === 0) return   // already granted

    await this.grants.grantFor(orderId)
  }
}
```

The conditional `update` is the pattern to internalize. The
[ledger](/docs/payments/concepts/idempotency) already stopped the redelivery; this stops everything
else — a manual replay, a reconcile, a second code path.

## A card subscription with a trial

```ts title="app/services/subscribe_service.ts"
const subscription = await getPayments().driver('credit_card').createSubscription({
  customerId: user.billingCustomerId!,
  planId: 'plan_pro',
  amount: 4990,
  cycle: 'MONTHLY',
  trialDays: 14,
  startDate: '2026-09-01',
  externalReference: `sub:${localSubscription.id}`,
  card: {
    token: cardTokenFromFrontend,        // tokenized in the browser
    holder: { name, email, cpfCnpj, postalCode, addressNumber, phone },
    remoteIp: request.ip(),
  },
})
```

The card number never touches your server — the frontend tokenizes, you send the token. The gateway
then charges that token every cycle and sends a webhook per charge.

From there the billing layer keeps `billing_subscriptions` in sync on its own. What you own is the
reaction:

```ts title="app/payment_handlers/subscription_canceled.ts"
static readonly eventType = 'subscription.canceled'

async handle(event: WebhookEvent) {
  const ref = (event.data as { externalReference?: string }).externalReference
  await this.access.revokeAtPeriodEnd(ref)
}
```

<Callout title="Asaas propagates the reference to every installment">
The webhook for the third monthly charge still carries the `externalReference` you set when the
subscription was created — so it routes back to your subscription row with no parsing. That is the
main reason to set it on subscriptions and not just on charges.
</Callout>

## Upgrading a plan mid-cycle

Two calls and a local record. Update the gateway subscription, then let the webhook confirm:

```ts
await getPayments().driver('credit_card').updateSubscription(subscription.gatewayId, {
  amount: 9990,
  description: 'Pro → Business',
})

await localSubscription.merge({ pendingPlanId: 'plan_business' }).save()
```

```ts title="app/payment_handlers/subscription_updated.ts"
static readonly eventType = 'subscription.updated'

async handle(event: WebhookEvent) {
  const ref = (event.data as { externalReference?: string }).externalReference
  const local = await Subscription.findBy('id', stripPrefix(ref))
  if (!local?.pendingPlanId) return

  await local.merge({ planId: local.pendingPlanId, pendingPlanId: null }).save()
}
```

Applying the new plan on the API response instead would give the customer the upgrade even if the
gateway rejected the change.

## Marketplace splits

Asaas splits a charge across wallets natively. Percentages, fixed amounts, or both:

```ts
await getPayments().driver('pix').charge({
  customerId,
  amount: 10_000,                       // R$ 100,00
  externalReference: order.id,
  split: [
    { walletId: seller.asaasWalletId, percentualValue: 90 },
    { walletId: partner.asaasWalletId, fixedValue: 500 },   // R$ 5,00
  ],
})
```

The gateway does the arithmetic on its side. When you compute a split yourself, do it in integers
and give the remainder to one recipient — see [Money](/docs/payments/concepts/money).

## Metered billing

Record consumption as it happens; price the period at the end.

```ts title="app/services/usage_service.ts"
// On every metered event
await store.recordUsage({ subscriptionId, meter: 'api_calls', quantity: 1 })
```

```ts title="app/jobs/close_billing_period.ts"
import { meteredBillForSubscription } from '@adonis-agora/payments'

const bill = await meteredBillForSubscription(store, {
  subscriptionId: subscription.id,
  from: periodStart,
  to: periodEnd,
  rates: [
    { meter: 'api_calls', rate: 0.5, included: 1000 },   // 1000 free, then R$0,005 each
    { meter: 'storage_gb', rate: 200 },
  ],
})

if (bill.total > 0) {
  await getPayments().driver('pix').charge({
    customerId: subscription.customerId,
    amount: bill.total,
    description: `Usage · ${periodStart.toISODate()} – ${periodEnd.toISODate()}`,
    externalReference: `overage:${subscription.id}:${periodEnd.toISODate()}`,
    idempotencyKey: `overage:${subscription.id}:${periodEnd.toISODate()}`,
  })
}
```

The `externalReference` and `idempotencyKey` both derive from the **period**, not from the moment the
job ran — so a job that runs twice charges once. See [Billing](/docs/payments/billing).

## Dunning — reacting to a failed payment

```ts title="app/payment_handlers/payment_failed.ts"
static readonly eventType = 'payment.failed'

async handle(event: WebhookEvent) {
  const data = event.data as { externalReference?: string; reason?: string }
  const subscription = await Subscription.findBy('id', stripPrefix(data.externalReference))
  if (!subscription) return

  const attempts = subscription.failedAttempts + 1
  await subscription.merge({ failedAttempts: attempts, status: 'past_due' }).save()

  if (attempts >= 3) {
    await this.access.suspend(subscription.id)
    await this.mail.send(new SubscriptionSuspended(subscription, data.reason))
  } else {
    await this.mail.send(new PaymentFailed(subscription, attempts))
  }
}
```

Reset `failedAttempts` on the next `payment.succeeded`, or a customer who recovers stays one failure
from suspension forever.

## Refunds

Check the capability first — not every gateway has one:

```ts
const driver = getPayments().driver(payment.provider)
getPayments().assertCapability(driver, 'refunds')   // Woovi/OpenPix throws here

const refund = await driver.refund(payment.gatewayId, partialAmountCents)
```

The refund still confirms by webhook. Revoke on `payment.refunded`, not on the API response:

```ts title="app/payment_handlers/payment_refunded.ts"
static readonly eventType = 'payment.refunded'

async handle(event: WebhookEvent) {
  const ref = (event.data as { externalReference?: string }).externalReference
  await this.grants.revokeFor(ref)
}
```

## A billing dashboard

`billingOverview` is the headless data contract behind one — pure store queries, no gateway calls,
so it is fast and trivially testable:

```ts title="app/controllers/billing_dashboard_controller.ts"
import { billingOverview, LucidBillingStore } from '@adonis-agora/payments'

const overview = await billingOverview(new LucidBillingStore(), {
  from: DateTime.now().startOf('month').toJSDate(),
  to: DateTime.now().toJSDate(),
})

// overview.metrics:
// [{ key: 'revenue', label: 'Revenue (cents)', value: 1_284_900 },
//  { key: 'active_subscriptions', label: 'Active subscriptions', value: 212 },
//  { key: 'meter:api_calls', label: 'Usage · api_calls', value: 481_230 }]
```

Revenue is the sum of **paid** payments in the window, in cents. Format at the edge; see
[Money](/docs/payments/concepts/money).

## Handler dispatches, durable does the work

The shape to reach for when the grant is more than one update. The webhook answers in milliseconds
and the actual work gets checkpointing and retries:

```ts title="app/payment_handlers/payment_succeeded.ts"
@inject()
export default class PaymentSucceededHandler {
  static readonly eventType = 'payment.succeeded'
  constructor(private engine: WorkflowEngine) {}

  async handle(event: WebhookEvent): Promise<void> {
    const ref = (event.data as { externalReference?: string }).externalReference
    if (!ref) return
    await ProcessPaymentWorkflow.dispatch({ externalReference: ref }, { runId: `pay:${event.id}` })
  }
}
```

Keying the run id on the **event id** means a redelivery that somehow got past the ledger still
produces one run. Belt and braces on the path where it is cheapest.

Three gaps found wiring a real B2B subscription in `gateway` mode.

**`externalReference` now survives on subscriptions.** `CreateSubscriptionInput.externalReference` is documented as the id webhook handlers route on, and the column already existed — but `saveSubscription` had no field for it, `SubscriptionListItem` did not expose it and `listSubscriptions` could not filter by it. So the app could send the id, watch the gateway echo it onto every charge, query payments by it, and still have no way to ask "which subscription belongs to this customer of mine?". Added to the store contract, to the returned item and to a new `SubscriptionListQuery`. Related: gateway-mode `SubscriptionsApi.create()` never persisted a subscription row at all, leaving the record to appear only if and when a webhook arrived; it now writes one at creation.

**`arrears(store, { externalReference })`.** `renewalFailureCount` and friends are filled by this library's renewal pass, which only runs for `managed` subscriptions — in `gateway` mode (the default) the gateway retries and those fields stay null forever. Answering "is this customer behind, and since when?" meant walking `billing_payments` by hand in every app. The helper does it once, including the non-obvious part: the arrears are dated from the START of the current failure run, because dunning retries the same bill for days and dating from the newest attempt keeps resetting the clock on the customer who is furthest behind.

**A provider slot may now be `undefined`, and is skipped.** Every declared provider was built during boot and drivers validate credentials in their constructor, so `payments.asaas({ apiKey: env.get('ASAAS_API_KEY') })` without a key did not disable payments — it stopped the process from starting, which hits CI and every developer machine. `payments.when(condition, () => payments.asaas({ apiKey }))` defers the construction and leaves the slot out. A provider that IS declared and throws still fails the boot, and `ASAAS_WEBHOOK_TOKEN` still refuses to boot on purpose: a missing API key means "cannot charge", a missing webhook token means a public route that marks invoices paid for anyone who posts to it.
